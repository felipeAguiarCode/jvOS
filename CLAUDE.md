# JARVIS OS

As specs, as decisões e as regras do projeto ficam em [`.specs/`](.specs/README.md). Leia o índice antes de mudar comportamento.

- **Uma spec por item:** cada pasta de `.specs/features|widgets|apps/` e de `.specs/foundation/` (architecture, stack, `vendor/<lib ou modelo>`) tem um único `spec.md` no formato do [spec-coding.dev](https://spec-coding.dev/tools/): Objetivo, Não-objetivos, Critérios de aceite (`### Critério N` com Dado/Quando/Então), Casos de borda nas quatro categorias, Entregáveis (com Testes e Reversão) e Dependências. No meio fica o corpo SpecLang (dados, componentes com Comportamento/Layout/Estilo, voz), com os IDs US/RF/RNF/SC. As de `features/` seguem o formato **Feature Specification** (`.specs/_templates/feature.md`, modelo em `.specs/features/reminders/spec.md`): títulos em inglês, conteúdo em PT-BR, critérios `AC-00N`, limitações `KL-00N` e decisões em aberto `OQ-00N`.
- **Pediram uma feature (nova ou mudança):** use a skill do projeto `feature` (`.claude/skills/feature/SKILL.md`). Ela planeja primeiro em `.specs/features/<id>/spec.md`, no formato Feature Specification, e só depois implementa ([ADR-0026](.specs/arch/adr/0026-feature-comeca-pela-spec.md)).
- **Feature, widget, app ou ADR novo:** comece com `npm run new` (ou `npm run new -- <widget|app|feature|adr> <id> --yes …`; `--help` lista as flags). O CLI cria o `spec.md` a partir de `.specs/_templates/` e os esqueletos de código, sem editar nenhum arquivo existente. Depois, aplique o checklist de registro que ele imprime (está também em Tarefas › Fase 2 da spec).
- **Mudou comportamento:** atualize o `spec.md` da pasta: o bullet do componente, os Critérios de aceite, os Casos de borda, os Entregáveis e as Tarefas (numa feature: Requirements, Acceptance Criteria, Behavior and Flows, Test Strategy, Implementation Plan e Known Limitations). Se mudou contrato, atualize também `.specs/arch/ipc-contract.md` e `.specs/domain/persistence.md`. Dependência nova ou trocada: atualize a spec de `.specs/foundation/vendor/` e a de stack.
- **Decisão de arquitetura:** crie um ADR novo em `.specs/arch/adr/` com o próximo número. Um ADR aceito não é editado; ele é substituído por outro.
- **Antes de codar:** siga `.specs/arch/constitution.md`, `coding-style.md` e `testing.md`. Um spec Playwright novo só roda se estiver no `testMatch` do projeto `ui`.
- **O README continua mínimo:** nada de tabelas de atalhos, frases, testes ou dados. Isso fica em `.specs`.
- **Idioma:** UI e conteúdo das specs em PT-BR (os títulos das seções das features ficam em inglês); código, comentários e commits em inglês.
